# AnnLite v0.1.0 — Monorepo Foundation

**Pray. Learn. Hope. Serve.** (*Priye. Aprann. Espere. Sèvi.*)

First release of the consolidated AnnLite monorepo, built by the Berline Britus project.

## Highlights
- 🏗️ **One repository, clear boundaries:** `apps/{web,mobile,admin}`, `backend`, `database`, `content`, `payments/{core,celoht,cards}`, `design-system`, `security`, `infrastructure`, `tests`, `docs`.
- 💳 **Payments core (tested):** payment state machine, HMAC-SHA256 webhook verification with replay protection, idempotency, and on-chain verification of CELO / USDm donations. Client-side "success" is never trusted.
- 🔁 **History-preserving migration:** `scripts/import-legacy.sh` brings existing repositories in via `git subtree`.
- 📚 **Documentation:** architecture, trust boundaries, payments, security, migration map, ADR 0001.
- 🔒 **Automation:** CI, CodeQL, Dependabot, dependency review.

## Verification
- `payments/core`: **7/7 tests passing**, TypeScript typecheck clean.
- Not yet verified: web, mobile, admin, backend, database, Visa/Mastercard and CeloHT end-to-end flows (legacy code not imported yet).

## Known limitations
- `apps/*`, `backend` and `database` are placeholders until legacy code is imported.
- No live card provider connected.
- The Celo smart contract is **unaudited — not for mainnet**.
- Two overlapping legacy repository families (`annlite-*`, `ann-lite-*`) must be reconciled (see `docs/governance/MIGRATION.md`).

## Upgrade / next steps
1. Run `./scripts/import-legacy.sh --dry-run`, then without the flag.
2. Reconcile duplicates, run `pnpm install && pnpm test`.
3. Archive old repositories only after full validation.
